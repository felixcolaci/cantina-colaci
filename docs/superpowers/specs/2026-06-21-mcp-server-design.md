## Overview

An MCP (Model Context Protocol) server embedded in the Cantina Colaci Next.js app that lets Claude access your cellar inventory during any conversation. When planning a dinner or menu, Claude can look up which wines you actually have in stock and recommend pairings from your real collection — not hypothetical ones.

**Example flow:**
> Felix: "Ich plane heute Abend Saltimbocca alla Romana, was passt dazu aus dem Keller?"
> Claude: *calls `get_cellar_wines`* → "Du hast einen 2019er Frascati von Casale Marchese (3 Flaschen, Klimaschrank Treppe) und einen 2018er Chianti Riserva — beide würden sehr gut passen, der Frascati ist aber näher am klassischen Römer Begleiter…"

## Architecture

The MCP server runs as a Next.js Route Handler at `/api/mcp`. It implements the **Streamable HTTP transport** (modern MCP standard, supported by Claude Desktop and claude.ai).

Authentication uses a **personal API key** — a UUID generated by the user, stored hashed in Supabase, and configured in Claude Desktop's MCP server list. One key maps to one family's cellar.

```
Claude Desktop / claude.ai
        │  POST /api/mcp
        │  Authorization: Bearer <api-key>
        ▼
Next.js Route Handler (/api/mcp/route.ts)
        │  validate key → resolve family_id
        │
        ▼
Supabase (service role)
  → storage_locations, wines, cellar_entries
```

The endpoint uses the Supabase **service role key** (server-side only, never exposed to clients) so it can bypass RLS and query directly by `family_id` resolved from the API key.

## Data Model Change

### New table: `api_keys`

| Column | Type | Notes |
|---|---|---|
| id | uuid | PK |
| family_id | uuid | FK → families |
| name | text | e.g. "Claude Desktop" |
| key_hash | text | SHA-256 of the actual key (key itself never stored) |
| created_at | timestamptz | |

No RLS needed — this table is only accessed via the service role key in the MCP endpoint.

## MCP Tools

### `get_cellar_wines`

Returns all in-stock wines for the family's cellar. Claude uses this data plus its own knowledge to suggest pairings.

**Input:** none

**Output:** JSON array of wines:
```json
[
  {
    "name": "Brunello di Montalcino",
    "producer": "Casanova di Neri",
    "vintage": 2017,
    "type": "red",
    "region": "Toscana",
    "country": "Italy",
    "grape_variety": "Sangiovese Grosso",
    "quantity": 4,
    "storage_location": "Klimaschrank Treppe",
    "notes": "Für besondere Anlässe"
  }
]
```

## UI Changes

### New: `/settings/api-keys` — API Key Management

Accessible from the profile dropdown. Owner can:
- Generate a new API key (shown **once**, then only the name is visible)
- See existing keys by name + creation date
- Revoke keys

After generating, the page shows a ready-to-paste Claude Desktop config snippet:

```json
{
  "mcpServers": {
    "cantina-colaci": {
      "url": "https://cantina-colaci.vercel.app/api/mcp",
      "headers": {
        "Authorization": "Bearer <your-key>"
      }
    }
  }
}
```

## Security Notes

- The actual API key is shown exactly once after generation — never stored, only its SHA-256 hash
- The Supabase service role key lives only in Vercel environment variables (`SUPABASE_SERVICE_ROLE_KEY`), never in client-side code
- The MCP endpoint is read-only: it only exposes `get_cellar_wines`, no write operations
- Each key is scoped to one family — cross-family access is impossible

---

## Out of Scope (v1)

- Write tools (adding wines via MCP)
- Multiple cellars per family (uses the first/primary cellar)
- Wine search/filter tools (Claude can filter the returned list itself)
- OAuth-based auth for MCP (personal API key is sufficient for personal use)
